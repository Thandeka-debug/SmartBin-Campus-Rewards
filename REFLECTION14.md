## Word Count: Approximately 600 words

## 1. How I Improved My Repository Based on Peer Feedback

My classmates told me that my CONTRIBUTING.md needed clearer setup instructions. They also suggested adding a features table to the README so new contributors could easily find tasks to work on.

Based on this feedback, I added step-by-step installation commands to CONTRIBUTING.md including git clone, cd, and pip install. I also created a Features for Contribution table in the README with difficulty levels and label names like good-first-issue and feature-request.

The feedback also helped me improve my issue labels. I made sure each good-first-issue had clear acceptance criteria so beginners would know exactly what to do. I also added more detail to the feature-request issues to explain the scope of each feature.

## 2. Challenges in Onboarding Contributors

The biggest challenge was making the setup process work for everyone. Different classmates had different Python versions and operating systems. Some struggled with installing the requirements because they were missing pip or had older Python versions that were not compatible.

Another challenge was writing clear issue descriptions. It was difficult to break down tasks into small enough pieces for beginners. I had to balance between too much detail and too little, making sure each issue was understandable without being overwhelming for a first-time contributor.

Time management was also a challenge. Creating documentation, labeling eight issues, and responding to feedback from classmates took more time than I expected. I learned to prioritize tasks by importance, focusing on the README and CONTRIBUTING.md files first before working on other documentation.

## 3. Lessons Learned About Open-Source Collaboration

This assignment taught me valuable lessons about open-source collaboration.

First, documentation is essential. Without clear CONTRIBUTING.md and README.md files, no one would know how to help with the project. Good documentation saves time for both project maintainers and new contributors.

Second, issue labels guide contributors. Labels like good-first-issue help beginners find tasks that match their current skill level. Feature-request labels help organize future development and show what features the project maintainers want to add.

Third, peer feedback improves quality. My classmates saw things that I missed, such as links that did not work correctly and instructions that were unclear. Having other people review your work is valuable for finding blind spots.

Fourth, stars and forks show engagement. Getting 32 stars and 33 forks from my classmates showed that they found my project worth noticing and saving. This is motivating for continued development and shows that my work has value to others.

## Summary

This assignment taught me how to prepare a repository for open-source collaboration. I learned to write clear documentation, label issues properly, and gather peer feedback. The experience of receiving 32 stars and 33 forks from my classmates showed that my project was well-received. I will use these practices in future open-source projects.
